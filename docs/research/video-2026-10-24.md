# Video support and linked repository review

Reviewed on 2026-10-24. These repositories are references, not evidence that Veil clears SynthID:

- [cebeuq/Synthid-Bypass](https://github.com/cebeuq/Synthid-Bypass/blob/main/README.md): V2 is a ComfyUI image workflow using Qwen diffusion reconstruction, Canny guidance and a Z-Image face pass. It is generative, requires large models and can alter details. It is not a drop-in native iOS, non-generative video method. Veil does not import its workflow or model weights.
- [froggeric/gemini-watermark-and-synthid-remover](https://github.com/froggeric/gemini-watermark-and-synthid-remover/blob/main/README.md): the visible video overlay path reverses a known alpha blend, with scene/occlusion handling and audio passthrough. This does not invert an invisible content-conditional watermark. Its SynthID path uses SDXL regeneration; its README reports a small manually verified image sample and explicitly lists video SynthID among open work. Spectral approaches and an unreliable proxy detector were removed by that project. Its results do not establish efficacy of Veil's phase heuristic.

The video implementation is independent Swift/AVFoundation code. No third-party code, calibration assets or neural models from these projects are bundled. The inherited constraint is no generative redrawing: Veil instead runs its bounded image filter on upright frames, preserves recognized text before compression, stabilizes only the correction, retains sample timestamps and passes through compressed audio.

Apple's [reader output settings](https://developer.apple.com/documentation/avfoundation/avassetreadertrackoutput/outputsettings) specify that nil settings vend original compressed samples in decode order. This is used for audio and metadata-only video remuxing. Apple's [FileRepresentation](https://developer.apple.com/documentation/coretransferable/filerepresentation) supports copied file imports for large movies without holding the entire payload in memory.

## Validation scope

The native `VideoSmoke` diagnostic generates a portrait, variable-frame-timing H.264/AAC clip with readable text, moving geometry, a tone and a private test metadata title. It checks frame count, original presentation timestamps, exact compressed audio payload hash and timestamps, displayed orientation/dimensions, duration, missing source container metadata, decoded color/geometry error, text recognition after lossy encoding, and exact compressed video payloads in metadata mode. A silent clip is also checked. Artifacts contain generated clips only. Unit tests check temporal-mask resets, cancellation cleanup and invalid imports; UI tests process a synthetic portrait clip and switch before/after previews.

These are media-integrity and quality checks. They do not measure SynthID removal, a video classifier's score or physical iPhone speed, peak memory and thermals. Actual efficacy requires known-positive original videos and official before/after detector results. No such result is claimed. The app continues to show “SynthID не проверен”.

# Upscaling and processing performance, 2026-10-24

The implementation adds a standalone video upscaler and a selectable scaling step in pattern mode. It enlarges to a 1920 or 3840 px long side, retaining aspect ratio and already larger sources. It is non-generative interpolation, with no neural detail synthesis, motion-compensated warp or new frames. Missing information and unreadable lettering cannot be recovered by this method.

The Metal scaler uses two separable shape-preserving cubic passes through a float intermediate. Local endpoint clamps prevent interpolation ringing; optional source cleanup is limited to one common RGB level in low-contrast neighborhoods. The 12-level contrast gate freezes pronounced boundaries. This is not complete codec-block removal. Low-contrast lettering and source compression artifacts remain a limitation. H.264 output introduces its own compression.

## Measured build and controls

[Native diagnostic run 40125588699](https://github.com/CORBENDALLAS111/Veil/actions/runs/40125588699), source `50ce20eba99b892e9ea19de2113b8d2d08c61f5e`, Xcode 26.2, macOS CI, GPU reported as **Apple Paravirtual device**. Generated media only; no user photos or videos were uploaded.

The diagnostic compiles the actual released 0.7 pattern and video implementations from `dd70bf6333ab2ea0bf7eb04e5d1fe4239cf00f26` alongside the current implementation. Shared raster/resampler helpers were unchanged. The two filter versions receive the same 1280×720 textured calibration raster and the same OCR rectangles.

| Filter strength | 0.7 filter | Optimized filter | Pixel equality |
| --- | ---: | ---: | --- |
| Gentle | 113.66 ms | 114.15 ms | Exact |
| Balanced | 107.54 ms | 96.43 ms | Exact |
| Strong | 111.23 ms | 98.34 ms | Exact |

These are single filter calls, including lazy coefficient initialization. Gentle was effectively unchanged in this run; the other two were about 10–12% faster. They do not establish speed on every image or device. Caching coefficients avoids repeated trigonometry; video additionally removes two bitmap readbacks. No OCR quality reduction or frame skipping is used.

## Scaling-only comparison

CPU monotone reference versus Metal, same 720p source and target. Metal timing is the mean of three warm render calls; CPU timing is one call. Data readback, movie encoding, OCR and model/pipeline initialization are not included in these render timings. Metal initialization was measured separately at 449 ms.

| Target | CPU scaling | Warm Metal scaling | Ratio | Maximum difference from CPU |
| --- | ---: | ---: | ---: | ---: |
| 1920×1080 | 98.93 ms | 2.98 ms | 33.2× | 1/255 |
| 3840×2160 | 280.02 ms | 6.12 ms | 45.7× | 0/255 |

The known “FLOW 2026 • SALE 19.99” label remained recognized after both enlargements. One-level GPU/CPU differences are expected from floating-point/UNORM rounding. This does not guarantee semantic recognition of arbitrary text. The optional cleanup's measured maximum channel change at source dimensions was 1/255.

## Full export comparison

The generated 720p movie has only **three frames over one second**, a moving shape, text and AAC audio. It is a short functional/performance control, not a representative long 24/30 fps Flow clip.

The full pattern+4K path took **3.852 s in 0.7** and **3.263 s after optimization**, a **1.18×** speed ratio, about **15% less elapsed time**. Scaling-kernel ratios must not be advertised as full-export acceleration. Standalone upscale exports took 0.329 s (1080p) and 0.233 s (4K); cache/startup effects dominate such short clips, so this does not imply 4K is generally faster than 1080p.

Both standalone exports retained all source frame timestamps and the exact compressed audio payload hash/timestamps. The encoded lettering remained recognized. Existing portrait/VFR, silent clip, metadata remux, cancellation, image/text/4K and simulator checks remain in the release gate.

## Limits

No physical iPhone runtime, sustained throughput, battery/thermal behavior or peak-memory measurement is available. GPU buffers are reused within an export and cleared afterward. CPU fallback preserves the reference interpolation when Metal initialization is unavailable, with different speed. No official SynthID test was performed by this benchmark, and upscaling is not proof of watermark removal or camera origin. The app continues to display “SynthID не проверен”.
